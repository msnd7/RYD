# منصة إدارة مجمع رياض القرآن

منصة عربية متكاملة لإدارة مجمع **رياض القرآن** لتحفيظ القرآن الكريم — مدينة الملك سعود السكنية بديراب،
تجمع إدارة المساجد الثلاثة ومتابعتها في مكان واحد:

- **جامع عبدالله بن عمر**
- **جامع ماجد بن مترك**
- **جامع عبدالله الضحيان**

كل مسجد له إدارته المستقلة (فريق عمل، لجان، معلمون، حضور، مهام، طلب مالي مستقل)،
ومدير المجمع يتابعهم جميعًا من شاشة واحدة.

---

## النشر والتخزين

المنصة تعمل بوضعين، وتكتشف وضعها تلقائيًا:

| | **مشترك (Vercel + قاعدة بيانات)** | **محلي (بلا خادم)** |
|---|---|---|
| مكان الحفظ | قاعدة بيانات PostgreSQL | متصفح الجهاز |
| مشاركة البيانات | الجميع يرى نفس البيانات من أي جهاز | كل جهاز على حدة |
| كلمات المرور | مُجزّأة على الخادم (scrypt) | في المتصفح |
| الاستخدام | التشغيل الفعلي | المعاينة والتجربة |

**للنشر على Vercel وربط قاعدة بيانات دائمة: اتبع [DEPLOY.md](DEPLOY.md)** — أقل من عشر دقائق.

## التشغيل

```bash
npm install
npm run dev            # الواجهة فقط (حفظ محلي) — http://localhost:5173
npm run build          # نسخة الإنتاج داخل مجلد dist
npm run dev:api        # الواجهة + الخادم + قاعدة البيانات — http://localhost:3000
npm run preview        # معاينة نسخة الإنتاج
npm run build:single   # نسخة بملف HTML واحد داخل dist-single (للمشاركة السريعة)
npm run typecheck      # فحص أنواع الواجهة والخادم
```

## الدخول وإدارة الحسابات

الدخول **بالبريد الإلكتروني ورمز الدخول**. تبدأ المنصة نظيفة تمامًا بلا أي بيانات تجريبية،
ولا يوجد فيها سوى حساب واحد يُنشأ تلقائيًا عند أول تشغيل:

| الحساب | البريد الإلكتروني | الرمز المبدئي |
|---|---|---|
| مدير المجمع | `msnd5033@gmail.com` | `1234` |

### مسار التهيئة

1. **مدير المجمع** يدخل بالرمز المبدئي، فتظهر له فورًا شاشة **إلزامية** لتعيين رمز خاص به
   (لا يُقبل الإبقاء على الرمز المبدئي).
2. يضيف المدير **مشرف كل مسجد** بالاسم والبريد الإلكتروني، فيُنشأ الحساب برمز مبدئي `1234`،
   وتظهر بطاقة **بيانات الدخول** جاهزة للنسخ والتسليم.
3. عند أول دخول للمشرف تظهر له شاشة **تغيير الرمز** الإلزامية نفسها.
4. بعدها يتولّى **مشرف المسجد** إضافة فريق عمله ومعلمي مسجده وبياناتهم.
5. **إعادة التعيين**: من `الإعدادات ← الحسابات والدخول` يعيد المدير رمز أي شخص
   إلى الرمز المبدئي، ويُطلب منه تغييره عند الدخول التالي.

> الرمز المبدئي نفسه قابل للتغيير من الإعدادات.

## التطبيق والإشعارات (PWA)

المنصة مهيّأة للعمل كتطبيق قابل للتثبيت:

- **أندرويد / ويندوز (Chrome, Edge)**: تظهر دعوة تثبيت داخل المنصة، أو من قائمة المتصفح ⋮ ← «تثبيت التطبيق».
- **آيفون / آيباد (Safari)**: زر المشاركة ⬆️ ← «إضافة إلى الشاشة الرئيسية».
- تعمل بدون إنترنت بعد أول فتح (Service Worker يخزّن الواجهة والخطوط والشعار).
- **إشعارات التذكير**: تُفعَّل من `الإعدادات ← التطبيق والإشعارات`، وتنبّه باقتراب مواعيد
  المهام والقرارات والتوصيات أو تأخّرها.

> التذكيرات تصل ما دام التطبيق مفتوحًا أو مثبّتًا على الجهاز. ولإرسالها والتطبيق مغلق تمامًا
> يلزم ربط خدمة Push على خادم — و`public/sw.js` مهيّأ لاستقبالها.

## ما الذي تقدّمه المنصة؟

### ٠) من يرى ماذا

لكل صلاحية مساحتها، ولا يرى أحد ما لا يخصّه:

| | **مدير المجمع** | **مشرف المسجد** | **الموظف / عضو اللجنة** |
|---|---|---|---|
| الوجهة عند الدخول | واجهة المجمع | مسجده مباشرة | مساحته الخاصة |
| المساجد | الثلاثة جميعًا | مسجده فقط | — |
| لوحة المجمع والمقارنات | ✅ | — | — |
| الموظفون والمعلمون | ✅ | مسجده | — |
| المهام | كل المهام | مهام مسجده | **مهامه ومهام لجنته فقط** |
| التحضير | الجميع | موظفو مسجده | نفسه |
| العهد | اعتماد وإقفال | طلب | طلب لعهد لجنته |
| الإعلانات | نشر للجميع | نشر لمسجده | ما وُجّه إليه أو للجميع |
| المالية والإعدادات والنطاق المكاني | ✅ | — | — |

المنع مفروض على **الخادم** لا في الواجهة فقط: أي محاولة للوصول إلى شاشة أو
بيانات خارج الصلاحية تُعاد إلى مساحة صاحبها.

### ٠٫٥) النظام الليلي والنهاري
زر في أعلى الصفحة يبدّل بين النظامين، ويتبع إعداد الجهاز افتراضيًا،
ويُحفظ اختيارك لكل جهاز. التقارير تُطبع دائمًا بخلفية بيضاء ونص داكن.

### ٠٫٦) تنظيم الواجهة
- **قائمة جانبية مجمّعة** في أربع مجموعات: المتابعة اليومية · المسجد وفريقه · التوثيق والتواصل · المالية والإعدادات.
- **ترويسة موحّدة لكل شاشة**: اسم الشاشة وسطر يشرح وظيفتها والإجراء الرئيسي — فلا تحتار أين أنت وماذا تفعل.
- **قوائم إجراءات منسدلة (⋯)** بدل تكدّس الأزرار في كل صف.
- **شريط إحصاءات هادئ** بلون واحد للتنبيه فقط، بدل البطاقات الملوّنة المتزاحمة.
- **شريط تنقل سفلي** على الجوال لأهم خمس شاشات.
- **قائمة المهام** بتصميم مبسّط: لوحة بطاقات ملوّنة تعمل كمرشّحات (الكل · قيد التنفيذ ·
  منجزة · متعثرة · مؤجلة · متأخرة)، وكل بند بلون حالته وشريط جانبي، وعلامة إنجاز بضغطة،
  و**زر تذكير عبر واتساب** يفتح رسالة جاهزة للمسؤول على رقمه المسجّل.

### ١) الشاشة الرئيسية للمجمع
- بطاقة لكل مسجد تعرض: المشرف، عدد فريق العمل والمعلمين، حضور اليوم،
  نسبة الحضور خلال ٣٠ يومًا، المهام المفتوحة والمتعثرة، العهد المفتوحة.
- **صندوق «ما يحتاج قرارك اليوم»** — ابتكار يجمع في مكان واحد كل ما ينتظر تدخّل المدير:
  طلبات الاستئذان، طلبات العهد، العهد المتأخرة عن الإقفال، المهام المتعثرة والمتأخرة،
  العقود غير الموقّعة، والمساجد التي لم تُسجّل حضور معلميها اليوم.
- **لوحة المجمع** فيها جدول مقارنة المساجد الثلاثة جنبًا إلى جنب (حضور الفريق، حضور المعلمين، الإنجاز، المصروف).

### ٢) لوحة معلومات كل مسجد
حضور اليوم، نسب الحضور، حالة المهام، أداء اللجان، المعلمون اليوم، آخر الإعلانات وأقرب المواعيد.
(المالية غير مدرجة في اللوحة كما هو مطلوب، ولها صفحة مستقلة محمية.)

### ٣) الإداريون والمعلمون — فرق واضحة الصلاحيات

| | الإداري (فريق العمل) | المعلم |
|---|---|---|
| من يضيفه | المدير يضيف المشرف، والمشرف يضيف بقية الإداريين | مشرف المسجد |
| له حساب دخول | ✅ ببريده الإلكتروني | — لا يحتاج حسابًا |
| التحضير | يحضّر **نفسه** داخل نطاق المسجد | **المشرف** يرصد حضوره أو غيابه |
| الاستئذان | يرفع طلبه بنفسه | **المشرف** يرفع الطلب نيابةً عنه |
| الراتب والخصومات | من بياناته في صفحة الإداريين | من راتبه المسجَّل في صفحة المعلمين |

في الحالتين يعتمد **مدير المجمع** طلب الاستئذان، ويُخصم نصف يوم بدل يوم كامل.
ويُسكَّن الإداري في لجنة أو أكثر فيظهر اسمه تلقائيًا في صفحة اللجنة وقوائم إسناد المهام.

### ٤) المهام والقرارات والتوصيات
- بمجرد اختيار **المسؤول** تُملأ **لجنته** تلقائيًا، وباختيار **اللجنة** يُقترح **رئيسها** مسؤولًا.
- لكل بند: النوع (مهمة / قرار / توصية)، الحالة (منجز / متعثر / مؤجل / قيد التنفيذ)،
  التاريخ المحدد، ومدة التنبيه قبل الموعد — كلها قوائم منسدلة.
- كل لجنة تضيف مهامها الخاصة وتفوّضها لأحد أعضائها من صفحة اللجان.
- **إشعار الدخول**: يظهر لكل مستخدم عند دخوله بالبنود التي اقترب موعدها أو تأخرت،
  ويختفي تلقائيًا بعد ١٠ ثوانٍ (المدة قابلة للتغيير من الإعدادات).

### ٥) التحضير بالنطاق المكاني
- يحدّد المدير لكل مسجد إحداثيات ونصف قطر النطاق من **إعدادات المسجد**
  (مع زر «استخدام موقعي الحالي» وزر اختبار «هل أنا داخل النطاق؟»).
- المشرف يحضّر نفسه كل يوم من حسابه، ولا يُقبل التحضير إلا داخل النطاق، وتُحفظ المسافة مع السجل.
- تظهر نسبة الحضور وعدد أيام الغياب، ويمكن رفع **طلب استئذان** يعتمده المدير.
- الربط المالي: **الغياب يخصم يومًا كاملًا، والاستئذان المعتمد يخصم نصف يوم**،
  وتُحتسب قيمة اليوم من الراتب المسجّل على أساس أيام العمل الشهرية (قابلة للضبط).

### ٦) محاضر الاجتماعات
محضر على مستوى المجمع أو المسجد أو اللجنة، مع المكان والتاريخ والوقت،
وقائمة الحاضرين تتغير تلقائيًا حسب نطاق الاجتماع. المحضر قابل للعرض والطباعة بتنسيق رسمي.

### ٧) التقارير
- **تقرير شخصي**: نسبة الحضور والغياب والاستئذان، الأثر المالي، والبنود الموكلة (المنتظرة والمتعثرة والمتأخرة).
- **تقرير لجنة**: المنجز والمتعثر والمؤجل، أداء كل عضو، وتقييم عام للفترة.
- **تقرير المسجد / المجمع**: مقارنة شاملة.
- **تقرير المعلمين**: حضورهم وتقييمهم.
- **التقارير الدورية المرفوعة**: كل مسجد أو لجنة ترفع تقريرها الأسبوعي أو الشهري
  مدعومًا بالشواهد (صور أو ملفات).
- كل التقارير بتصميم مميز و**تُطبع أو تُحفظ PDF بمنطقة التقرير فقط** — لا تُطبع واجهة المنصة.

### ٨) الإعلانات والرسائل
موجّهة للجميع أو لمسجد أو للجنة أو لشخص بعينه عبر قائمة منسدلة، مع إمكانية التثبيت.

### ٩) مساعد التنسيق الذكي ✨
عند كتابة إعلان أو محضر أو تقرير أو تفاصيل مهمة، يظهر زر **«تنسيق ذكي»**
يقترح صياغة أفضل (تصحيح إملائي شائع، ضبط الترقيم، ترتيب النقاط، مقدمة وخاتمة مناسبة)
ويعرضها بجوار نصك، ولك الخيار: **اعتماد الصياغة الجديدة** أو **الإبقاء على كتابتي**.

يعمل حاليًا محليًا داخل المتصفح بدون إنترنت. ولربطه بنموذج لغوي حقيقي، ضع عنوان الخدمة
في **الإعدادات ← مساعد التنسيق الذكي** (خدمة تستقبل `{ text, kind }` وتعيد `{ text }`).

### ١٠) الإدارة المالية والعهد (للمدير ومن يفوّضه)
- الصفحة لا تظهر إلا للمدير أو لمن فعّل له **«تفويض بالوصول للإدارة المالية»**.
- **لكل لجنة زر «طلب صرف عهدة»** في صفحة اللجان، وتظهر عهدها أسفل بطاقتها بحالتها ومتبقّيها.
- دورة العهدة: **طلب** (المبلغ، الغرض، تاريخ الإقفال، المسؤول عن الاستلام) ← **اعتماد المدير**
  ← **عهدة مفتوحة** ← تسجيل كل مصروف **بفاتورة إلزامية** (صورة أو ملف) ← **الإقفال**
  مع إعادة المبلغ المتبقي. لا يُسجَّل مصروف بلا فاتورة، وتُحتسب المصروفات من مجموع الفواتير.
- **مسيّر الرواتب** في جدولين: **الإداريون** و**المعلمون**، كلاهما مربوط بالحضور والغياب والاستئذان.
- تقرير مالي قابل للطباعة.

### ١١) العقود والتوقيع على الشاشة
لكل عامل عقد يعرض بياناته وبنوده وربطه بالحضور والخصومات، ويوقّع عليه **بالرسم على الشاشة**
(باللمس أو الفأرة)، فيُحفظ التوقيع في سجله ويظهر في العقد، والعقد قابل للطباعة.

### ١٢) المعلمون
**مشرف المسجد وحده** يسجّل بيانات معلمي مسجده (الحلقة، **المرحلة**: الابتدائية أو المتوسطة
أو الثانوية أو الجامعيون أو الموظفون، عدد الطلاب، الجوال، **الراتب الشهري**)،
ثم يرصد حضورهم اليومي (حاضر / متأخر / مستأذن / غائب)، **ويصحّح أي رصد خاطئ بمسحه**،
ويرفع لهم **طلب استئذان** يعتمده المدير، وتُحتسب الخصومات من رواتبهم تلقائيًا.
ويكتب ملاحظات التقييم، ويشارك تقريرهم أو يطبعه.

## البيانات والنسخ الاحتياطي

في الوضع المشترك تُحفظ البيانات في قاعدة PostgreSQL:

- جدول `ryd_state`: وثيقة واحدة تحمل كل بيانات المجمع، ومعها رقم إصدار.
  عند تعارض حفظين، يُعاد تطبيق تعديلك فوق النسخة الأحدث تلقائيًا فلا يضيع عمل أحد.
- جدول `ryd_files`: الفواتير والشواهد، تُقدَّم عبر `/api/files/<id>` لأصحاب الجلسات فقط.
- المتصفح يسحب تحديثات الآخرين كل عشر ثوانٍ وعند العودة للتبويب، وتظهر حالة الحفظ
  في أعلى الصفحة (**محفوظ** / **جارٍ الحفظ** / **تعذّر الحفظ** / **حفظ محلي**).

في الوضع المحلي تُحفظ في `localStorage` وتُزامَن بين تبويبات المتصفح فقط.

في الحالتين: **الإعدادات ← البيانات** فيها **تصدير** نسخة كاملة بصيغة JSON
و**استيرادها**، و**إعادة التهيئة** من الصفر.

## واجهة الخادم (API)

| المسار | الوظيفة |
|---|---|
| `GET /api/health` | هل قاعدة البيانات متصلة؟ |
| `POST /api/auth/login` | دخول بالبريد والرمز، ويضع كوكي جلسة موقّعة |
| `GET /api/auth/session` | المستخدم الحالي |
| `POST /api/auth/logout` | خروج |
| `POST /api/auth/change-password` | تغيير الرمز (يتحقق من الرمز الحالي) |
| `POST /api/auth/reset-password` | إعادة تعيين رمز حساب — للمدير فقط |
| `GET /api/state` · `PUT /api/state` | قراءة وكتابة وثيقة المجمع بالتحقق من الإصدار |
| `POST /api/files` · `GET /api/files/:id` | رفع الفواتير والشواهد وتنزيلها |

## الهوية البصرية

- **الشعار**: شعار مجمع رياض القرآن الأصلي دون أي تعديل على رسمه — أُزيلت خلفيته البيضاء
  وهوامشه الفارغة فقط (`src/assets/logo.png`)، فصار يظهر حرًّا بلا إطار أو مربع،
  ومنه وُلّدت أيقونات التطبيق.
- **الخط**: خط **ثمانية** على كامل واجهات المنصة، مضمَّن محليًا في `src/assets/fonts`
  ونسخة الترخيص في `public/fonts/ThmanyahFont-License.pdf`:
  **Thmanyah Sans** للنصوص، و**Thmanyah Serif Text** للعناوين (أهدأ وأكثر انضباطًا من Display).
- **الألوان**: الأزرق الغامق والبرتقالي فقط:
  `navy` من `#EEF3F9` إلى `#04121F` (الأساسي `#12395F`)،
  و`orange` من `#FFF7EE` إلى `#5A2D06` (الأساسي `#F0820E`).
  حتى الرسوم البيانية وحالات المهام تستخدم درجات هذين اللونين فقط.

## البنية التقنية

```
src/
├── components/      # مكونات الواجهة (بطاقات، نوافذ، رسوم بيانية، توقيع، تنسيق ذكي)
├── pages/           # الشاشات
├── lib/             # التاريخ، المسافات الجغرافية، التنسيق الذكي، الاستعلامات
├── store/           # قاعدة البيانات والجلسة
├── data/seed.ts     # قاعدة نظيفة: المساجد الثلاثة ولجانها وحساب المدير فقط
└── types.ts         # نماذج البيانات
```

React 18 + TypeScript + Vite + Tailwind CSS، بواجهة عربية RTL بالكامل،
ومتجاوبة مع الجوال (آيفون وأندرويد) والتابلت والآيباد والحاسب:
شريط تنقل سفلي على الجوال، وقائمة جانبية على الشاشات الكبيرة، وجداول تتحوّل إلى بطاقات،
مع احترام المساحات الآمنة (notch) ومنع تكبير الحقول في iOS.
